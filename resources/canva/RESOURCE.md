## Purpose

Canva is the design tool of choice for marketers and non-designer teams creating visual assets — social posts, presentations, campaign materials, documents. The Canva MCP integration lets Hornero skills create designs from brand templates, generate designs with AI, edit existing designs programmatically, export to standard formats, and manage assets and folders. Primary consumers: designers (brand-template workflows, bulk export), marketing (campaign asset creation, brand-kit management).

## MCP Server

**Canonical integration:** `mcp__claude_ai_Canva__` — the native Canva integration in claude.ai. Enable it via **Settings → Integrations → Canva** and authenticate via Canva's OAuth. No API key or local server needed.

The Canva integration exposes one of the richest MCP tool sets available in claude.ai. It is the only supported integration path — there is no community self-hosted MCP server for Canva.

**Capabilities exposed:**

**Auth:** OAuth via claude.ai. Canva's OAuth grants access to the authenticated user's designs and the teams/brands they're a member of.

## Object Model

- **Design** — a Canva project. `id` is an opaque design ID. Has `title`, `thumbnail`, one or more `pages`, `owner`, `created_at`, `updated_at`. The `type` distinguishes presentation, document, social media post, etc.
- **Page** — one slide or canvas within a design. Pages have `id`, `title` (optional), and a list of `elements`. A single-page design (e.g., social post) has exactly one page.
- **Asset** — an uploaded image, video, or font in the user's media library. Has `id`, `name`, `mimeType`, `url` (pre-signed download link). Assets are reusable across designs.
- **BrandKit** — a set of brand guidelines: palette colours, fonts, logos, and icons. Tied to a Canva Team. Skills generating brand-aligned content should pull the active brand kit to stay on-brand.
- **Folder** — a container for designs and sub-folders. `id` is the folder ID. The root is the user's home folder.
- **Comment** — a review annotation on a design. Has `id`, `author`, `body`, `position` (canvas coordinates), `created_at`, child `replies`.

**Relationships:**
- Design → 1..N Pages
- Page → 0..N Elements (text, image, shape — returned as structured content by `get_design_content`)
- Folder → 0..N Designs, 0..N Folders (nested)
- Design → 0..N Comments; Comment → 0..N Replies

## Common Gotchas

- **Editing requires a transaction.** You cannot call `perform_editing_operations` without first opening a transaction with `start_editing_transaction`. Always pair start/commit or start/cancel — an uncommitted transaction may leave the design in an intermediate state.
- **`generate_design` vs. `generate_design_structured`.** `generate_design` takes a free-text prompt and returns a design generated by Canva AI. `generate_design_structured` takes a structured brief (title, dimensions, elements spec) — prefer structured when you need predictable output for a brand template.
- **Brand kit fonts are not system fonts.** Fonts from a brand kit are loaded in the Canva rendering environment but will not be available for download as raw files. If exporting to DOCX or PDF, fonts are embedded in the export.
- **Export formats vary by design type.** `get_export_formats` returns the formats available for a specific design. Not all designs support all formats — a presentation can export to PPTX; a social post cannot. Always call `get_export_formats` before `export_design`.
- **`merge_designs` is destructive.** Merging combines pages from multiple designs into one. The source designs are not automatically deleted, but the merged output is a new design. Verify source designs before merging in automation scripts.
- **Thumbnail URLs are time-limited.** `get_design_thumbnail` returns a pre-signed URL that expires. Don't cache the URL — re-fetch when needed.
- **Comments are positional.** `comment_on_design` takes canvas coordinates (x, y). If the design is resized after comments are added, coordinates may reference points that no longer map to the original element.
- **Team scope.** Designs in a team workspace are only visible if the authenticated user is a team member. Personal designs are always accessible; team designs require membership in that team.

## Fallback Without MCP

The Canva Connect API (REST) is available for self-hosted alternatives, but it uses a different authentication model (client credentials + scopes) from the claude.ai OAuth integration:

```sh
# Get a design (requires Connect API access token, not the same as claude.ai OAuth)
curl "https://api.canva.com/rest/v1/designs/DESIGN_ID" \
  -H "Authorization: Bearer ${CANVA_ACCESS_TOKEN}"
```

The Canva Connect API is not a direct fallback for the MCP integration — it has a separate approval process and scope model. For automated design workflows without the MCP integration, evaluate the Connect API separately.
